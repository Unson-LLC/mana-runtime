# 議事録のボタン操作にすぐ応答し、受付と完了を区別する

## User story

議事録を投稿する利用者として、保存先ボタンを押した直後に共有済みと誤認せず、処理受付・完了・失敗を区別して確認したい。これにより、キュー受付や処理本体が失敗した場合も、成功したと思って待ち続けずに済む。

## 受け入れ基準

- 署名・入力・操作対象のローカル検証後、外部の権限照会を待たずにSlackへ受付応答を返す。実処理はバックグラウンドで継続する。
- 権限確認後、キュー受付前の保存先表示は「保存先が選択されました。処理の開始を確認しています」とし、ボタンを取り除く。生成開始・受付成功・共有完了を先取りしない。
- テナントの権限確認と各外部操作の認可は維持する。保存先・ファイル名・処理状態を含む表示にも認可を適用する。機密情報を含まない本人だけの受付表示は認可待ちから切り離す。
- 受付後の表示は「処理中」であり、共有完了を意味しないことを明記する。
- キュー受付が失敗した場合は、成功表示を一度も出さず、処理ID・失敗段階・エラーコードを表示する。
- 議事録の作成・共有が完了した場合だけ、既存の完了通知と共有URLを表示する。
- 自動テストで表示順序と失敗時の表示を固定する。

## 保存先操作の対象範囲

| 操作 | 先に表示する状態 | 続く処理 |
| --- | --- | --- |
| ワークスペース選択 | プロジェクト一覧を開いています | プロジェクト一覧 |
| ワークスペース一覧へ戻る | ワークスペース一覧を開いています | ワークスペース一覧 |
| プロジェクト・保存先選択 | 処理の開始を確認しています | キュー受付・議事録生成 |
| 保存先をやり直す | 保存先のやり直しを確認しています | 本人だけに確認を表示 |
| やり直しを確定 | やり直しの開始を確認しています | 本人だけに状態を表示・キュー受付 |

HTTP受付は全5経路で外部認可より前に返す。同時に、署名・app・操作ユーザー・入力・ローカルの操作対象を検証したresponse_urlへ「操作を受け付けました。確認しています。」を本人だけに表示する。保存先やファイル名は含めず、共有メッセージも変更しない。この受付は外部認可・操作の台帳・キューを待たず、失敗しても実処理を止めない。

保存先一覧と詳細な状態は認可後、受付停止チェックより先に更新する。受付表示の配信時間と認可完了時間をクリック単位のログで分離する。Slack通信時間は残るため、本番の表示速度は実操作で別途確認する。

## 対象外

- 議事録から抽出したタスクの編集・取消・担当者選択・編集モーダル（別のタスク操作経路）
- 議事録生成内容の変更
- 保存先設定の変更
